# Implementation decisions

Recorded during inline execution on October 16, 2026. Costs describe what may need revision if a decision proves wrong.

- Ruling: Use the native managed worktree on a new local branch. It isolates the approved implementation without changing main; no external publish or merge is involved. Cost if wrong: branch/worktree reconciliation is required.
- Ruling: Xcode license acceptance blocks compilation. Follow the approved plan's source-work allowance while user acceptance is pending; author tests first and record blocked runs without calling them successful RED/GREEN cycles. Cost if wrong: compiler issues remain undiscovered until the license is accepted.
- Task 4: Ruling: XCTest UI runner times out enabling automation mode before any test executes. Use existing CUA native automation for interactive UI acceptance and keep the XCTest UI test source; do not grant new security permissions or claim the automated UI suite passed. Cost if wrong: UI regressions have less automated coverage.
- Task 5: Ruling: Add a core-only test scheme so filesystem tests do not depend on the unavailable UI automation service. Keep the one app-producing scheme unchanged. Cost if wrong: scripts/schemes need maintenance in two places, with the same core suite.
- Task 8: Ruling: Keep journal as a required separate executor dependency instead of mixing journal I/O into FileOperationBackend; add supportsAtomicMove capability to the filesystem boundary so real cross-volume behavior can be simulated accurately. Cost if wrong: constructor/adapter maintenance, no user-visible feature change.
- Task 9: Ruling: Add conflictID to conflict resolution, make shelf staging/resolution asynchronous, and limit shelf result removal to captured entry UUIDs. This rejects stale sheet actions, avoids blocking the UI on mounted folders, and preserves freshly restaged items; cost if wrong: additional API arguments and async callers. A shared OperationGate serializes short actions with transfers because actor reentrancy alone cannot serialize awaited I/O.
- Task 12: Ruling: Use an exclusively created private staging container and identity-checked cleanup, with payload inside it. A regression test proved copyfile can treat a pre-existing staging directory as a container even with COPYFILE_EXCL; a random name alone was not ownership proof. Cost if wrong: incomplete private staging containers require review, rather than removing unrelated files.
- Task 12: Ruling: Native drag acceptance remains unverified. CUA attempts reach the source pasteboard callback but produce no completed dragging session/drop; the XCTest UI runner also stalled before assertions. Preserve standard AppKit drag handlers and an executable UI regression test, and disclose the validation gap rather than claim success. Cost if wrong: drag behavior may require a follow-up fix on real pointer input.
- Task 12: Ruling: SwiftUI exposes no Close command-group replacement; its built-in Close targets NSWindow directly and bypassed a content responder. Use a per-window delegate bridge that forwards all other callbacks to the existing SwiftUI delegate, preserving explicit window close and Settings behavior. Cost if wrong: additional window-delegate lifecycle/compatibility maintenance. Native two-tab Command-W now preserves the same window with one tab.
- Task 12: Ruling: Retain row-entry scroll anchors without a pixel offset, use static RuntimeIdentity properties, and keep recovery review non-destructive without automatic replay/cleanup. These are narrower internal interfaces than the plan sketches. Cost if wrong: partial-row scroll alignment is not restored, call sites need adaptation, and recovery is manual rather than resumable.
